## Findings

### 1. [Fixed] Preview toolbar CSP error on UAT — production-hygiene, QA surface only
The document CSP sets `script-src 'self'` (deliberately strict — it guards the
in-browser code sandbox). Vercel injects its **preview toolbar**
(`vercel.live/_next-live/feedback/feedback.js` + a pusher websocket) into
non-production deployments, so on UAT that script is CSP-blocked and logs an
error on **every page load** — desktop and mobile. Noise on the exact surface
the team uses for QA.

- **Not present on production** — verified: the toolbar is preview-only, and
  `grain.natejly.com`'s console carries no such error.
- **Fix (`apps/web/next.config.ts`):** gate the toolbar's own origins
  (`https://vercel.live`, `*.pusher.com`) onto the existing directives **only
  when `VERCEL_ENV` is `preview`/`development`**. Production stays byte-for-byte
  `self`-only; an unset `VERCEL_ENV` (non-Vercel build) falls on the strict
  side. Pinned by `apps/web/tests/csp-headers.test.ts` in both directions.

### 2. [No action — designed] Signed-out 401 / 503 console entries
On a signed-out load the browser logs a red `401` (`/api/auth/me`, the correct
response for no session) and a `503` (`/api/auth/google/start`, the frontend's
**availability probe** for unconfigured Google login — a non-200 hides the
button). Both are intentional and documented; the app handles them functionally.
Present on production too, but they are designed probes, not errors to fix.

### 3. [No action — deliberate design] Empty new-thread pane
A brand-new user's first thread is a blank pane above the composer. This is an
intentional choice, not an oversight — the code comment in
`components/views/chat.tsx` records that starter cards were *removed
deliberately* as "onboarding filler," leaving the composer placeholder as the
one instruction. Left as-is out of respect for the documented decision.
